# タスク管理(業務タスク)

池松さんの業務タスクを `tasks.md`(リポジトリ直下)1ファイルで管理する。
目的は「抱えている仕事を全部ここに出して頭を空ける」「締切を落とさない」「今日やることを迷わない」の3つ。
きっちりした管理より、**話しかけるだけで記録が続くこと**を優先する。

## tasks.md の形式

ファイルがなければ以下で新規作成する。

```markdown
# タスク一覧

最終更新: YYYY-MM-DD | 次のID: T004

## 未完了

- [ ] T001 練成工業様 GAS修正版を送付 | 期限: 2026-10-25 | 優先: 高 | 状態: 未着手 | 追加: 2026-10-23 | 更新: 2026-10-23
- [ ] T002 見積書の雛形を作る | 期限: なし | 優先: 中 | 状態: 進行中 | 追加: 2026-10-20 | 更新: 2026-10-22 | メモ: 前回版は 資料/ にある
- [ ] T003 関口油脂様 仕様確認 | 期限: 2026-10-24 | 優先: 中 | 状態: 待ち(先方回答) | 追加: 2026-10-21 | 更新: 2026-10-21

## 完了(直近30日)

- [x] T000 定例相談会③の準備 | 完了: 2026-10-22
```

- **ID**: `T` + 3桁の通し番号。ヘッダーの「次のID」を使い、採番したら1つ進める(アーカイブを読み直さずに済むように)。ユーザーは「T002終わった」とも「見積書の雛形終わった」とも言うので、どちらでも特定できるようにする。
- **期限**: `YYYY-MM-DD` または `なし`。「金曜まで」「来週頭」などの相対表現は **日本時間(JST)の今日** を基準に日付へ変換し、変換結果を返信で明示する(例:「金曜 = 10/30 として登録」)。
- **優先**: 高・中・低。指定がなければ、顧客の締切がある・他人を待たせている → 高、それ以外(自分が相手の返事を待っている場合も含む) → 中 と推定し、推定したことを伝える。
- **状態**: 未着手 / 進行中 / 待ち(誰の何を待っているか)。待ちは自分では進められないタスクなので、今日やることの候補から外し、代わりに催促の要否を見る。
- **更新**: 状態や内容を変えた日。放置検知に使うので、触ったら必ず更新する。
- 未完了は **期限が近い順(なしは最後)→ 優先度順** に並べ直す。開いたときに上から見れば済むようにするため。
- 完了セクションは新しい順。完了から30日を過ぎたものは、tasks.md を書き換えるついでに `tasks/archive/YYYY-MM.md`(完了月)へ移す。
- **今週** = 今日から5営業日以内(土日を除く)。金曜に聞かれても翌週前半の締切が視野に入るようにするため。

## 操作

ユーザーの発言から操作を判断する。1回の発言に複数の操作が混ざっていてもまとめて処理する
(例:「見積書終わった。あと来週水曜までに請求書も」→ 完了1件+追加1件)。

### 追加
- 「〇〇をやる」「〇〇しないと」「〇〇頼まれた」などから、タスク名・期限・優先・顧客名を抜き出す。
- タスク名は **動詞で終わる具体的な行動** に整える(「見積書」→「見積書を作って送る」)。何をすれば終わりか分かる名前にすると、着手のハードルが下がるため。
- 同じ内容の未完了タスクがあれば新規追加せず、既存タスクの更新として扱い、そのことを伝える。
- 曖昧でも聞き返さずに仮で登録し、仮定を明記する。聞き返すのは「誰の・何の」タスクかすら分からない時だけ。
- 「メール出した、返事待ち」のように自分の行動が済んでいる場合は、**返事が来たら自分がやること** をタスク名にし(例:「関口油脂様 回答を受けて仕様を確定する」)、状態を 待ち、メモに「MM/DD 送付済み」と残す。

### 完了
- 該当タスクを「完了」セクションへ移し、`完了: YYYY-MM-DD` を付ける。
- 候補が複数あって特定できない時だけ確認する。
- 返信では一言ねぎらい、残りの期限が近いタスクを1つだけ添える。

### 更新
- 「〇〇は先方の返事待ち」→ 状態を 待ち に。「〇〇着手した」→ 進行中。「〇〇は来週に延期」→ 期限変更。
- 延期が同じタスクで2回目以上になったら、責めずに「分割するか、やらない判断をするか」を1行で提案する。

### 一覧
- 未完了を「期限切れ / 今日・明日 / 今週 / それ以降・期限なし / 待ち」に分けて表で出す。待ちのタスクは期限があっても「待ち」に入れる。該当なしの区分は省く。
- 列は ID・タスク・期限・優先・状態。完了済みは聞かれない限り出さない。

### 今日やることの提案
「今日何やればいい?」「今日の段取り」などで使う。

1. Google カレンダーのツールが使えれば今日(JST)の予定を取得し、空き時間の合計をざっくり出す。
   【ET課】朝礼/夕礼 と「〇〇飲み」は予定として数えない。使えなければ空き時間は推定せずに進める。
2. 候補の選び方(この順):
   期限切れ → 今日期限 → 明日期限で高優先 → 今週期限の高優先 → 進行中のもの。待ちは除く。
3. **メインは3件まで** に絞る。空き時間が少ない日(会議・会食で埋まっている日)は1〜2件にする。
   詰め込むと結局できずに自己嫌悪になる、というパターンを避けるため。候補が少ない日は無理に3件に埋めない。
4. 各タスクに「**最低ここまで**」を1行付ける(CLAUDE.md の約束破りリカバリールール)。
   例:「見積書 → 最低ここまで: 金額表だけ埋めて上長に見せる」。完成度より「時間が来たら見せる」を優先させるため。
   「最低ここまで」はその日の提案でだけ決める(登録時には付けない。日によって使える時間が違うため)。
5. 下の「待ちすぎ」に当たるタスクがあれば「催促する?」と1行添える。

出力例:

```
今日の空き: 約3時間(会議2件)

| # | タスク | 期限 | 最低ここまで |
|---|---|---|---|
| 1 | T003 関口油脂様 仕様確認 | 今日 | 確認項目3つをメールで送る |
| 2 | T001 練成工業様 GAS修正版を送付 | 10/25 | 自分のアプリでテストまで |
| 3 | T002 見積書の雛形を作る | なし | 項目の洗い出しだけ |

催促候補: T005 小野電気商会様 回答待ち(5日経過)
```

### 期限切れ・放置の指摘
「やり残しある?」「放置してるのない?」で使うほか、**どの操作のときも** 以下に当てはまるものがあれば返信の最後に1〜2行だけ添える(毎回の長い警告はうるさいので短く)。

- 期限切れ: 期限 < 今日 の未完了
- 放置: 状態が 未着手/進行中 で、更新から7日以上経過
- 待ちすぎ: 状態が 待ち で、更新から5日以上経過

同じ返信の表や催促候補ですでに触れたタスクは、末尾で重ねて指摘しない。
指摘するときは責めない。各タスクに「今日やる / 期限を変える / 分割する / やめる」のどれにするかを提案する。
やめる判断も立派な前進として扱う(完了セクションへ `完了: YYYY-MM-DD(中止)` で移す)。

## 返信のスタイル

- 何を登録・変更したかを最初に1〜3行で伝える(仮定した期限・優先度は明記)。
- 表を使うのは一覧と今日の提案のときだけ。追加・完了だけなら短く済ませる。
- 口調は親しみやすく、責めない。

## 記録の保存

tasks.md を変更したら「最終更新」を今日にして、コミット & プッシュする
(例: `タスク: T004 請求書作成を追加、T002 完了`)。
提案・一覧表示だけでファイルを変えていない場合はコミットしない。

タスクの完了報告だけでは日次ログ(`logs/`)には書かない。ユーザーが1日の活動として報告してきた場合は、
CLAUDE.md の日次フローでログに記録し、該当するタスクがあればこのスキルで完了にもする。
